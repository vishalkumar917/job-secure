# sample_data - DEMO DATA, NOT REAL FORENSIC EVIDENCE

`demo_case/` contains **synthetic** JSON files in the same shape as Volatility 3's JSON renderer
(`vol -r json <plugin>`). They are generated by `scripts/generate_demo_data.py` and exist so the platform
can be demonstrated without a real memory image.

* The data was **not** extracted from any real system or real malware.
* External IP addresses are RFC 5737 documentation addresses (192.0.2.0/24, 198.51.100.0/24, 203.0.113.0/24);
  domains use the RFC 2606 reserved `.example` TLD.
* Hexdumps contain only short, publicly documented byte prologues followed by zero padding - no functional code.
* Every case, analysis, export and report created from this bundle is labelled
  **"DEMO DATA - NOT REAL FORENSIC EVIDENCE"**.

Scenario: a user opens a macro-enabled document → `WINWORD.EXE` spawns encoded PowerShell (download cradle)
→ a masquerading `svchost.exe` runs from `C:\Users\Public` with injected executable memory containing a PE
header, a C2-like connection on port 4444, a handle to `lsass.exe` and SeDebugPrivilege → it starts
`rundll32.exe` with a DLL from `%TEMP%` (plus an unlinked DLL) and a child process that is unlinked from the
active process list. Benign processes (Defender, Chrome) include JIT-like executable memory to show how the
engine down-weights common false positives.

Regenerate with `python scripts/generate_demo_data.py`. Editing the bundle changes its SHA-256, which the
integrity check will detect.
