# Testing

```bash
cd backend
.venv/Scripts/python -m pytest          # Windows
.venv/bin/python -m pytest              # Linux/macOS
.venv/bin/python -m pytest --cov=app    # with coverage
```

Frontend type-check and production build:

```bash
cd frontend
npm run typecheck
npm run build
```

The backend suite has **110 tests**. They run against an isolated temporary data directory and SQLite
database (configured in `tests/conftest.py`), use the deterministic AI engine, and need no network.

| File | What is verified |
|---|---|
| `test_evidence_intake.py` | SHA-256 correctness; read-only storage under a generated name; extension allow-list; rejection of ZIP/PDF/PE/ELF/minidump/hibernation files; truncated files; crash-dump header detection; size limit with temp-file cleanup; filename sanitisation; deterministic bundle hashing. |
| `test_volatility.py` | Parsers on Volatility-format fixtures (column variants, `N/A`, 1601 timestamps, >2^63 addresses, nested `__children`, hexdump bytes); OS identification (Win10/11, Server 2019, uncertainty reporting); **the real subprocess runner** driven by a fake Volatility CLI: JSON parsing and output hash, symbol-error translation, timeout kill, legacy plugin-name fallback, secret stripping from the child environment, plugin allow-list, evidence-path and YARA-path confinement, PID sanitisation. |
| `test_detection.py` | Path normalisation; hidden/terminated processes; PID-reuse-aware parent lookup; truncated names; every rule positive and negative (masquerading, typo-squats, parents, hiding needs cross-view, duplicates, memory rules with JIT reduction, DLL side-loading, network, lsass handle trust-by-path, SeDebugPrivilege); engine fault isolation; disabled/not-evaluated reporting; rule output contract; encoded PowerShell decoding; LOLBin patterns and benign negatives; IOC false-positive filtering and extraction from decoded payloads; scoring formula, caps, corroboration bonus, bounds and bands; end-to-end demo scoring. |
| `test_ai.py` | Retrieval for PID questions (process, findings, network, memory, parent); missing-PID detection; intent classification for all nine example questions; validator rejection of fabricated PIDs/IPs/binaries/citations; over-claim detection with negation handling; deterministic answers grounded for every example question; "Insufficient evidence" message; LLM hallucination → regeneration → accepted; persistent hallucination → marked uncertain; provider failure → deterministic fallback; explanations contain all 7 sections with evidence copied from the DB even when the LLM tries to supply its own. |
| `test_api.py` | Auth required, bad tokens, login lockout, security headers; case creation, upload, invalid uploads, hash verification, custody ordering; **real Volatility 3 against random bytes**: plugin failures are logged and the job fails gracefully with a clear message; full demo pipeline (summary counts, OS identification, integrity before/after, targeted `--pid` plugin runs, plugin rationale); process list/tree/detail; findings filters, status updates and explanations; network, memory, IOCs, CSV/JSON export labelling, timeline ordering; AI query/history/summary; report generation in all four formats with hash verification and custody records; rules/YARA/settings endpoints including YARA `include` rejection; dashboard; stored strings fit their declared column lengths (PostgreSQL enforces VARCHAR limits, SQLite does not). |

## Fixtures

* `tests/fixtures/volatility/*.json` - small Volatility-format samples exercising column variants and edge cases.
* `tests/fixtures/fake_vol.py` - a stand-in CLI used to test the real subprocess path deterministically.
* `sample_data/demo_case/` - the synthetic demo bundle (generated by `scripts/generate_demo_data.py`).

## Manual / system verification performed

* Full UI walkthrough in a headless browser: login → load demo → progress → all 17 pages → AI question,
  with zero browser console errors.
* `docker compose up` stack against **PostgreSQL**: demo analysis, all four report formats and a grounded
  AI answer. (This run found a VARCHAR length issue SQLite had hidden, which led to the column-length guard test.)

## Testing with a real memory image

1. Obtain an authorised image (see `docs/forensic-methodology.md`).
2. Upload it through the UI, start analysis and watch the Analysis log.
3. Confirm `windows.info` succeeded and the OS identification is plausible; check plugin failures.
4. Compare process counts with `vol -f image windows.pslist` run manually - results should match.
